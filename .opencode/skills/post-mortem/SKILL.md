## Post-mortem template

```markdown
# Post-mortem: [Nom du projet]

**Date :** YYYY-MM-DD
**Agent :** [Analyst / Architect / ...]
**Projet :** [Nom]

## Ce qui a bien marché
- ...
- ...

## Ce qui n'a pas marché
- ...
- ...

## Surprises
- ...

## Skills à mettre à jour
- [Skill] : ajouter [apprentissage]
- [Skill] : corriger [information obsolète]

## Actions pour le prochain projet
- [ ] ...
- [ ] ...
```

## Processus de mise à jour des skills
1. Chaque agent écrit son post-mortem
2. L'orchestrator consolide
3. Mise à jour des fichiers SKILL.md concernés
4. Les changements sont commités dans git

## Règles
- Honnêteté : documenter les échecs aussi bien que les succès
- Actionnable : chaque apprentissage mène à une action concrète
- Incrémental : les skills grandissent projet après projet
- Pas de blâme : l'objectif est d'apprendre, pas de trouver un responsable
